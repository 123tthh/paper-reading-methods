# 论文笔记的框架与格式规范

本规范与[方法手册](method-guide.md)共同使用：框架规定内容放在哪里，格式规定它如何被读者看见。本文件给出可直接执行的默认样式；用户明确要求的目标格式优先。方法来源与补充约定见[来源说明](source-map.md)。

## 1. 固定为三个正文一级章节

文档标题、论文链接、阅读范围、摘要放在正文前，不另占一级章节。

| 正文一级章节 | 默认二级章节 | 内容要求 |
|---|---|---|
| **1. 研究背景** | 1.1 当前研究进展；1.2 局限性与挑战；1.3 本文改进思路 | 交代“已有能力 → 具体困难 → 设计回应”，不是背景名词堆砌。 |
| **2. 方法论** | 2.1 预备知识；2.2 总体架构；2.3 核心模块与公式；2.4 训练策略；2.5 完整流程 | 先总后分，说明变量、输入输出、机制与公式；2.5 再分训练与推理。 |
| **3. 实验** | 3.1 设置与评价指标；3.2 主要结果；3.3 消融与机制验证；3.4 泛化、扩展与失败分析；3.5 结论与局限 | 每组结果对应一个待验证主张；总结与启发收在 3.5。 |

二级章节可按论文调整名称、合并或删减，三个一级章节保留。没有读到实验时，保留“3. 实验”并明确“本次未核实”，不补造结果。理论论文可在第三部分呈现其实际验证证据并解释类型。用户只问一个问题时直接短答，不套整篇框架。

本模板将总结并入“3.5 结论与局限”，保持三个正文一级章节。

## 2. 标题、字体与颜色

**蓝色用于标题编号，标题文字保持深色。** 不把整行标题改成蓝字。以下是浅色页面模板采用的 CSS 像素值；它们不是 Word 的磅值，也不保证不同系统的字形完全一致。

| 元素 | 字号 / 字重 | 行高 | 文字与编号 |
|---|---|---|---|
| 文档标题 | 34px / 500 | 约 55.25px | 深色 `#1F2329`，无编号 |
| 正文一级标题 | 26px / 500 | 36.4px | 编号 `#1456F0`，标题文字 `#1F2329` |
| 正文二级标题 | 22px / 500 | 30.8px | 同上，如 `2.1 预备知识` |
| 正文三级标题 | 20px / 500 | 28px | 同上，如 `2.5.1 训练流程` |
| 正文 | 16px / 400 | 26px | `#1F2329`；关键词与段首短标签加粗 700 |
| 表格文字 | 14px / 400 | 模板采用 22px | 表头 700；数字和变量维持明确对齐 |

可移植模板使用 `-apple-system, BlinkMacSystemFont, "Helvetica Neue", Tahoma, "PingFang SC", "Microsoft YaHei", Arial, "Hiragino Sans GB", sans-serif`，不捆绑专有字体。编号使用 `"Helvetica Neue", Consolas, sans-serif`。字体家族是声明和回退顺序，不代表每个字符实际用了同一字体。

使用有序层级编号与蓝色列表圆点。模板不跳级；通常到三级为止，更细内容用加粗标签。标题段前留白由模板统一设置，不用空行堆出间距。

## 3. 表格：表头样式与该写什么

### 3.1 统一外观

执行顺序固定为：**确定相邻正文左右边界 → 设置每张表总宽 → 分配列宽 → 实际查看左右边界 → 修正所有未达标表格 → 保存后复核**。总宽等于正文内容区宽度，各列宽度之和等于总宽；两列表、短内容表同样适用。表格放在正文层级，避免列表或色块的缩进让 `width:100%` 只占满更窄的父容器。只放大容器、不调整实际列宽不算完成。

工作记录逐表记录所在小节、类型、左右边界是否对齐、列宽是否填满、是否溢出和修正结果。不能只抽查；未通过项修正后再次核验。当前载体不能保证宽度时说明限制，不能将纯 Markdown 成稿宣称为已完成等宽排版。

- **表格与正文等宽，左右对齐是硬性验收项。** 在当前文档的正文内容区内，表格左边界等于正文左边界，右边界等于正文右边界；不是与浏览器、侧栏或整张页面等宽。窄变量列与宽解释列只改变内部比例，不改变总宽度。820px 只是模板当前正文宽度；实际文档按当前正文宽度适配。
- 对所有变量表、模块表、流程表和结果表逐张检查。列宽之和应等于正文内容宽度；移动端和打印版也不得依赖固定最小宽度造成水平溢出。不能只放大表格外框、缩小字体或保留大量未使用空列。

- 表头：底色 `#F2F3F5`，文字 `#1F2329`，14px、加粗、水平居中。
- 内容：白底、深色文字、常规字重；细边框 `#DEE0E3`、1px；单元格内边距 8px。
- **物理量/变量列上下左右居中**，变量必须使用原生 LaTeX 公式。含义列左对齐、顶部对齐，单元格内用**真正的无序列表**逐项解释（含义、来源、维度/单位和所属阶段），列表圆点使用平台蓝色默认样式。不要只在普通段落前输入“•”冒充列表。步骤编号或简短状态可居中；解释性长句不整体居中。
- 变量表保持窄符号列、宽定义列，模板默认 25% / 75%；不把具体像素宽度当作所有文档的硬限制。
- 不默认加彩色斑马纹、深色表头或整行高亮。结果中仅加粗有必要强调且可比较的数值；标明指标方向与单位。
- 表格放结构化对应关系；连续推导和大段解释放表外。宽表拆成“设置说明＋结果表”，不靠缩小字号塞入页面。

### 3.2 复用的表头与单元格内容

| 表格用途 | 默认表头 | 内容怎么写 |
|---|---|---|
| 变量定义 | **物理量与变量｜定义** | 一个符号一行；定义中写含义、维度/单位、时间轴和所属阶段。确有必要再拆出维度列。 |
| 完整训练与推理 | **步骤｜流程细节** | 两张表分开写。左列“步骤 n：动作名称”，右列写已知量、计算、输出、更新/冻结、状态传递。 |
| 困难与回应 | **局限/挑战｜设计回应｜预期作用** | 一行对应一个可解释的设计动机；证据放文字或链接。 |
| 模块接口 | **模块｜输入｜操作与输出｜学习/使用阶段** | 明确来源与去向，避免只列模块名。 |
| 实验证据 | **待验证主张｜对照与设置｜指标与结果｜出处与结论边界** | 报告基线、条件、试验规模、数值口径和图表出处；没核实则写待核实。 |

原图与自行重排的结果表须明确区分，不能虚构图表编号。

## 4. 色块、行内高亮与强调

### 4.1 色块外观与默认用途

每块采用 **1px 同色边框＋8px 圆角＋16px 内边距＋左侧约 20px 图标**。正文仍用深色 16px；开头短标签加粗。用图标和文字标签同时表达用途，不只靠颜色。

| 类型 | 背景色 | 边框色 | 默认用法 |
|---|---|---|---|
| 橙色 | `#FEEAD2` | `#FFBA6B` | 📎 论文/项目入口；🧭 本节核心问题或导读 |
| 绿色 | `#D9F5D6` | `#8EE085` | 📝 摘要或已经有证据支持的简短总结 |
| 浅红色 | `#FDE2E2` | `#F98E8B` | 💡 重点讲解、机制解释与追问 |
| 浅紫色 | `#ECE2FE` | `#AD82F7` | ✏️ 概念定义、容易混淆的量与对照 |

四类用途分别为绿色摘要、红色重点讲解、紫色概念解释、橙色背景介绍或序言。图标可按内容选择。颜色表达阅读层次，不代表“错误”“危险”或“已证实”；不要混淆概念解释与重点讲解。

色块用于摘要、导读或理解难点，不包住整个方法章节。长推导可在色块外逐步展开，块内留直接答案与结论。疑问紧邻对应机制，避免集中到文末脱离上下文。

### 4.2 行内高亮

| 高亮 | 模板色值 | 白底近似合成色 | 模板用途（统一后的约定） |
|---|---|---|---|
| 橙色 | `rgba(254, 212, 164, .8)` | `#FEDDB6` | 局限、原因、失败条件 |
| 黄色 | `rgba(255, 246, 122, .8)` | `#FFF895` | 核心设计或关键动作 |
| 紫色 | `rgba(205, 178, 250, .7)` | `#DCC9FC` | 容易混淆的定义或对照 |

高亮少量关键短句；不是每段都必须有颜色。加粗、行内高亮、整块底色分别承担关键词、关键句、独立解释的层次，避免三种效果反复叠加。目录点击时出现的临时定位高亮，不计入文档设计。

## 5. 原图、原表、公式与间距

完整精读必须实际插入关键原图、原表并逐项解释，具体执行[原图与原表操作规范](figures-and-tables.md)。仅图注、链接或自制汇总表不算完成。架构原图放在总体说明之后、模块拆解之前；实验图和原表放在对应主张旁。图下写编号、来源、读图结论，区分原图、重绘和解释性示意。模板正文宽度 820px，图片最大宽度 100%；这个宽度与响应式、打印规则属于可移植实现约定。

数学公式以 LaTeX 输入，使用目标编辑器的原生公式对象；独立成行，并在正文内容区内水平居中。先定义符号，再解释运算、机制与假设。表格中的物理量可在单元格内使用行内公式，但所在变量单元格仍需上下左右居中。不要用 Unicode 字符拼接代替公式，也不能把未渲染的 LaTeX 源码当成最终效果。HTML 导出可将已核实的 LaTeX 渲染为 MathML/KaTeX，保留源码并检查渲染。长公式先按等号或逻辑分组分行，不能越出正文右边界。

## 6. 不同载体如何执行

- **飞书等富文本**：采用真正的标题级别、表格表头行、色块与行内高亮；变量表优先使用原生文档表格，以支持公式、列表与单元格对齐。HTML 粘贴可能被转换为嵌入电子表格，必须检查块类型与实际列宽；无法表达所需格式时重建为原生文档表格。文档标题不计入三段正文的一级标题。按平台支持选择最接近的样式，并复查实际效果。
- **HTML**：复制[彩色模板](../assets/paper-note-template.html)及[样式表](../assets/paper-note-style.css)。页面的文档标题是 `h1`，正文一级是 `h2`、二级是 `h3`、三级是 `h4`；这仅是语义层级映射，视觉字号仍按上述规范。两文件一起移动，或将 CSS 内联以便单文件分享。
- **Markdown / 聊天**：采用[结构模板](../assets/paper-note-template.md)，用 `##`、`###`、`####`、表格、加粗与引用块保留结构；纯 Markdown 不能可靠锁定字体、字号、颜色、边框或单元格底色。不要声称已经复刻颜色。用户明确要视觉格式且未限定载体时，交付 HTML 版；用户指定 Markdown 时遵从并说明颜色限制。
- **Word / PDF**：只有任务要求该载体时再生成；通过当前 Agent 可用的文档工具映射字体、颜色和表格样式，并渲染核验。不要直接把 px 数字当成 pt。

交付检查：三个正文一级章节；标题编号与文字颜色分开；每张表与正文左右边界对齐；表头/行标题加粗且底色加深；变量列上下左右居中、含义单元格使用无序列表；变量/流程表用途匹配；绿色摘要、红色重点讲解、紫色概念解释、橙色导读按内容使用并带文字标签；数学公式以 LaTeX 原生渲染、独立成行居中；关键原图、原表实际可见且逐项解读，有编号、来源及页码，转录表已逐格核对，插图插表占位已替换；没有把待核实内容写成结果；没有横向溢出、遮挡或大段不必要的高亮。最终滚动查看全篇；云端交付还须确认保存成功。


## 行内物理量与方法讲解块（补充规范）

所有位置的物理量与数学变量都必须使用 LaTeX：包括正文、表格的符号列和解释列、图注、色块及流程说明，不限于独立公式。行内量使用原生行内公式；Markdown 使用 `$...$`，HTML 使用由 LaTeX 对应的 MathML/KaTeX 数学节点并保留 `data-latex`。例如正文写 $V_t$、$\lambda_r$、$s_t$、$a_t$、$\theta$（下标含义以论文为准），表格解释写 $H=32$、$\Delta t=0.02\,\mathrm{s}$，不要使用 sₜ、fω 或裸露的 theta 代替。单位用正体，向量、上下标、帽号及时间索引全篇一致；模型名、代码标识、图表编号及普通计数不必强行数学化。独立公式仍另起一行居中，行内公式跟随句子排版。

方法论中的红色重点讲解块与紫色概念解释块应覆盖主要理解断点，不能只在开头各放一块：预备知识处解释状态、观测与目标；架构处解释模块关系；核心机制处解释设计动机、梯度与参数更新；训练和部署流程处澄清信息可得性与执行差异。按论文实际内容选用，完整方法论通常分布 4–8 个红/紫块，每个重要机制至少有一处适合的概念或重点说明；短文可减少，不为凑数添加重复内容。红色回答“为什么这样设计、去掉会怎样”，紫色回答“这是什么、与相近概念有何区别”。每块保留简短标签和直接答案，紧邻相应机制，长推导留在块外，不整章铺底色。

验收时逐段、逐表扫描正文和所有单元格中的变量与单位，确认它们确实渲染为数学对象；检查红/紫块覆盖预备知识、关键机制及流程衔接，且标签和内容相符。不要把美元符号源码、Unicode 上下标或单纯更改字体当作 LaTeX 渲染。
