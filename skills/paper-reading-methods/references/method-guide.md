# 论文精读方法手册

这套方法把论文组织成一条可讲清楚的因果链：问题为什么出现，作者怎样拆开问题，各模块如何协作，公式如何实现机制，最后用什么证据检验它。它由已有研究笔记的组织方式提炼；方法来源见[来源说明](source-map.md)。

它尤其适合有模型架构、训练机制与实验验证的论文。其他类型论文可以保留“问题—机制—证据”主线，调整二级以下内容。完整笔记按默认的“研究背景—方法论—实验”三段框架组织；总结并入实验末尾，具体见[框架与格式规范](format-guide.md)。

## 1. 判断这次能读到什么

先确认论文版本、正文和附录是否可得、笔记覆盖到哪里，以及当前要解决的问题。精读不是以篇幅计量：一篇有数十页译文的页面，可能仍没有形成方法分析；一份不长的笔记，也可能已经完整回答研究问题。

从已有笔记蒸馏方法时，只有实际读到的梳理才提供证据。优先选择包含背景、方法拆解、机制解释或疑问解答的成形笔记；如果有完成标记，再与正文相互核对。仅上传 PDF、原文链接、书目、空白标题或制作中页面，不作为完整样本。无法访问单独记录。

针对新论文，只有摘要就先做范围明确的初读；已读方法但缺实验，就交付机制分析并说明实验尚未核实。不能用论文题目猜出用户原笔记的写法。

## 2. 用“困难与回应”组织背景

不要从名词百科开始。先交代当前技术做到了什么，再指出具体场景下还缺什么，最后说明本文为什么需要这些新设计。

| 要回答的问题 | 合格的表达 |
|---|---|
| 已有工作做到哪一步？ | 交代与本文最相关的能力或假设，保留必要前作关系。 |
| 为什么还不够？ | 说明约束、失败现象及后果，例如历史变长后哪部分计算或存储增加。 |
| 本文怎样回应？ | 将设计与它要缓解的困难一一对应。 |
| 新贡献是什么？ | 分清新机制、组合方式、训练方案与实验发现。 |

## 3. 先看整体，再沿图拆模块

先实际插入已核实的论文总体架构原图，标明图号、来源与页码，再用几句话说明全局接口；没有架构图时如实说明，可另画明确标注的解释性示意。随后沿数据流拆解，而不是逐段复述论文。每个模块可用下面的记录卡：

| 项目 | 需要写清的内容 |
|---|---|
| 目的 | 模块要处理哪个困难；为何不能只靠前一模块。 |
| 输入 | 来自传感器、数据集还是上一模块；符号、形状与可用时间。 |
| 操作 | 编码、注意力、采样、优化、控制或其他核心运算。 |
| 输出 | 产生什么表示或动作，下一步由谁使用。 |
| 学习方式 | 哪个损失影响它，参数更新或冻结，是否有传递状态。 |
| 代价与限制 | 需要的监督、计算、假设或部署条件。 |

图解不要止于“这里有三个模块”。要讲清箭头承载什么、哪些量是条件、哪些是预测目标；区分数据流、状态传递和梯度路径。正文、图、附录或代码出现冲突时，把冲突列出来，按可验证信息解释。

## 4. 公式解释：定义、推导、意义、边界

关键公式采用四步讲法：

1. **定义变量**：名称、维度、物理含义；区分不同时间轴。
2. **定位作用**：这是目标函数、状态更新、参数更新，还是输出映射？
3. **补齐推导**：只展开理解所必需的步骤，注明假设和省略项。
4. **回到机制**：这个式子改变了什么量，为什么有助于解决前面的困难，何时不成立。

“物理含义”不要求每个变量都对应真实力学量。对于表征学习，它也可以是信息的写入、读取、压缩或条件化作用，但应说明这是解释视角。

### 一个教学推导的检查示例

下面是为说明推导规范而写的**线性教学例子**，不是对目标论文真实实现的复述：

设列向量 $k\in\mathbb{R}^{d_k}$、$v\in\mathbb{R}^{d_v}$，矩阵 $W\in\mathbb{R}^{d_v\times d_k}$，并定义

$$
L(W)=\tfrac12\|Wk-v\|_2^2.
$$

则

$$
\nabla_W L=(Wk-v)k^\top,
\qquad
\Delta W=\eta vk^\top-\eta Wkk^\top.
$$

两项都具有 $d_v\times d_k$ 的维度。第一项写入当前键值关联，第二项扣除当前预测对应的部分。仅在例如 $W=0$ 的特定一步，或明确为了教学而忽略第二项时，才能简化为 $\Delta W\approx\eta vk^\top$。不能据此直接宣布一般非线性 TTT 与标准注意力完全等价。

类比可以先把更新比作“写笔记”、查询比作“翻笔记”，但要补充：参数记忆通常不保存原始数据的精确副本；容量、遗忘与干扰仍需讨论。避免把压缩说成无损或完美记忆。

## 5. 分别走一遍训练与推理

理解所有模块后，再模拟完整系统的一次运行。将训练的一次迭代与部署的一次循环分开写，以避免混淆训练时可见的信息和部署条件。

| 检查项 | 训练时 | 推理或部署时 |
|---|---|---|
| 已知信息 | 数据集提供哪些观测、标签、参考或未来动作？ | 运行时实际能观测到什么？ |
| 待生成量 | 网络预测什么，和什么作比较？ | 哪些量必须由模型生成？ |
| 优化 | 哪些损失作用于哪些参数？ | 是否存在在线更新，若有，更新什么？ |
| 状态 | 如何初始化、跨片段传递、截断梯度？ | 何时继承、何时重置，如何避免跨任务污染？ |
| 输出 | 生成训练信号或模拟行为的哪一步？ | 如何转成可执行动作，之后获得什么反馈？ |

每一列都按真实执行顺序描述。不要仅写“训练网络，部署使用”，也不要将未见过的实现细节填入流程。

有内外层优化、教师学生、冻结模块或分阶段训练时，额外列出“阶段—可见信息—更新对象—监督来源”。没有直接损失的上下文，仍可能通过后续状态影响其他时间步的损失；这需要沿计算关系判断。

复杂度也需说明口径：单步还是整段、关于历史长度还是模型规模、固定哪些维度。若某状态大小不随历史长度增长，不能直接推出整个系统的总计算量或实际延迟始终不变。

## 6. 在理解断点处提出问题

疑问不是附加的趣味问答，而是检查理解的工具。优先处理用户已问的问题与方法中真正影响后续理解的断点，例如：

- 更新了参数，为什么就能保留历史信息？
- 这个输入和另一个名字相似的变量，是同一个对象吗？
- 为什么冻结这一模块？放开后优化目标会怎样变化？
- 训练中知道的未来信息，部署时从哪里来？
- 哪些约束限制了设计空间，是否足以保证作者声称的性质？

回答顺序是：直接结论 → 机制或推导 → 小例子或类比 → 成立条件。沿着真实理解断点逐层追问，对回答中的强断言回到原文核实。

## 7. 以实验回答主张

将结果按研究问题组织，不按截图顺序堆放。实际插入主要结果与关键消融的原图、原表，并在图表后解释轴/行列、单位、比较条件、关键观察及结论边界。原表可用截图或逐项核对的忠实转录；下面的主张汇总表不能替代原表。提取、插入与验收见[原图与原表操作规范](figures-and-tables.md)。

| 主张 | 实验与对照 | 应报告的证据 | 结论边界 |
|---|---|---|---|
| 整体方法更有效 | 在何种任务和设置下比较哪些基线？ | 指标、数值、试验规模及图表位置。 | 仅限哪些任务、数据和条件？ |
| 某模块有作用 | 移除或替换该模块后的对照是否可比？ | 消融变化及其不确定性。 | 支持关联、机制解释还是更强因果结论？ |
| 可扩展、可迁移或可部署 | 改变什么规模、环境或硬件条件？ | 横纵轴、范围、成本、失败案例。 | 是否在测试范围外仍成立尚不可知。 |

记住三个常见区分：完成得分不等于整段成功率；相对增幅不等于百分点；一条曲线在已测范围内上升，不保证继续扩大仍有效。没有读到统计口径或原表时不编数值。

## 8. 最后压缩成能复述的结论

在“3. 实验”的末尾以“结论与局限”收束到四件事：研究问题、关键机制、最有力的证据、主要限制。总结只引入已经解释过的内容。可迁移启发可以写，但与作者已证明的贡献分开。

完成后自问：我能否不用原文句子说清输入输出？能否沿架构解释一轮训练和推理？能否解释关键公式的每个符号与假设？能否指出主要结论对应哪张表或哪项实验？如果不能，回到相应断点补齐，不靠增加篇幅掩盖它。

## 9. 选择合适的呈现形式

完整笔记使用三个正文一级章节，配合有序二、三级标题、术语的中英对应、变量表、训练与推理流程表，以及紧邻逐项解释的论文关键原图、原表。标题、表头、单元格、色块和高亮是交付的一部分，按[框架与格式规范](format-guide.md)执行；可直接复用[彩色模板](../assets/paper-note-template.html)。

一级与二级标题采用蓝色编号、深色文字，分别为 26px 和 22px。表头浅灰、加粗居中，解释性内容左对齐。色块承载摘要、导读或理解难点；它们帮助阅读，但不能替代逻辑结构。不同载体的能力要如实说明，纯 Markdown 不能锁定这些视觉属性。简短追问用连续几段即可。
