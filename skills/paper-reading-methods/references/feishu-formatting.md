# 飞书排版操作与验收

仅在用户已授权的目标文档上操作；规范链接是读取依据，不是写入目的地。

## 表格与正文对齐

1. 读取当前正文内容区的左右边界。以正文为参照，不以浏览器宽度或侧栏位置为参照。
2. 检查所有表格实际块类型和列宽。HTML 粘贴可能生成嵌入电子表格，并把每列设为约 105px；不因 HTML 写有 width:100% 就认为等宽。
3. 原生文档表格优先；变量表尤其需要原生公式、无序列表、水平及垂直对齐。嵌入电子表格只能在这些要求均能满足时保留。
4. 表格外边界应与正文边界一致，允许浏览器亚像素四舍五入的少量差异；列宽之和必须占满该宽度。变量表可约 25%/75%，流程表可约 25–30%/70–75%，其他表按内容分配。
5. 表头/行标题加粗并加深背景；变量单元格水平和垂直居中；含义单元格使用真正的无序列表，左对齐、顶部对齐。不能以普通文字圆点或全部内容居中替代。
6. 调整后退出编辑状态，查看完整表格及相邻正文；逐张确认，不只抽查第一张。宽表过密应拆表，不缩小到难读字号。

## 标题、色块与公式

- 使用真正的标题等级和蓝色编号；不要把普通正文误识别成一级标题，不用手动空行堆间距。
- 摘要绿、重点讲解红、概念解释紫、背景或导读橙；使用原生色块，保留简短标签。行内淡黄用于重点，淡紫用于概念。
- 数学表达使用原生 LaTeX。独立公式另起一行，并把所在段落设置为居中；仅插入 Equation 并不保证居中。
- 变量表中的符号可使用行内原生公式，所在单元格须上下左右居中。长公式按语义分行，保证不越出正文。
- 修改后查看公式实际渲染；未渲染的 LaTeX、空占位或错误公式不能算完成。

## 论文原图与原表的插入

按[原图与原表操作规范](figures-and-tables.md)完成素材清单与提取。将原图和原表截图上传并插入对应章节的实际图片块，或把原表忠实转录为原生文档表格；附件、外链、图注和占位提示不能替代图表。架构图在模块拆解之前；结果与消融图表紧邻相应主张，每项后面写读图/读表说明与结论边界。

检查图像是否真正显示、编号与页码是否正确、图例和脚注是否完整；保持图片比例，转录表逐格对照原文。完成后离开编辑状态并重开/读回相关区段，确认保存且图表仍能加载。不能只凭上传成功或插入 API 成功就宣称完成。

## 浏览器操作的可验证性

优先使用平台提供且当前 Agent 可用的文档 API 或编辑能力，并读回验证。通过浏览器操作时，只依据当前可见或可访问的编辑器状态进行修改。每步读回状态；菜单与文档异步渲染时，先定位新状态再执行下一动作。不要复用失效的坐标或虚拟化后已经消失的块定位。

粘贴富文本后检查原生段落、表格、加粗与色块是否保留；有的粘贴接口会把 HTML 当普通文本。填充可编辑块可能触发自动编号，替换文字时应明确选择目标文本并检查结果。外部副作用和发布权限始终服从当前任务授权。

最终检查目录、表格边界、四类色块、公式居中、图片清晰度和来源，确认保存成功后交付链接。


## 行内物理量与方法讲解块（补充规范）

所有位置的物理量与数学变量都必须使用 LaTeX：包括正文、表格的符号列和解释列、图注、色块及流程说明，不限于独立公式。行内量使用原生行内公式；Markdown 使用 `$...$`，HTML 使用由 LaTeX 对应的 MathML/KaTeX 数学节点并保留 `data-latex`。例如正文写 $V_t$、$\lambda_r$、$s_t$、$a_t$、$\theta$（下标含义以论文为准），表格解释写 $H=32$、$\Delta t=0.02\,\mathrm{s}$，不要使用 sₜ、fω 或裸露的 theta 代替。单位用正体，向量、上下标、帽号及时间索引全篇一致；模型名、代码标识、图表编号及普通计数不必强行数学化。独立公式仍另起一行居中，行内公式跟随句子排版。

方法论中的红色重点讲解块与紫色概念解释块应覆盖主要理解断点，不能只在开头各放一块：预备知识处解释状态、观测与目标；架构处解释模块关系；核心机制处解释设计动机、梯度与参数更新；训练和部署流程处澄清信息可得性与执行差异。按论文实际内容选用，完整方法论通常分布 4–8 个红/紫块，每个重要机制至少有一处适合的概念或重点说明；短文可减少，不为凑数添加重复内容。红色回答“为什么这样设计、去掉会怎样”，紫色回答“这是什么、与相近概念有何区别”。每块保留简短标签和直接答案，紧邻相应机制，长推导留在块外，不整章铺底色。

验收时逐段、逐表扫描正文和所有单元格中的变量与单位，确认它们确实渲染为数学对象；检查红/紫块覆盖预备知识、关键机制及流程衔接，且标签和内容相符。不要把美元符号源码、Unicode 上下标或单纯更改字体当作 LaTeX 渲染。
